# 需求規格書：ISSUE-0053 功能選單新增資料庫同步入口、支援本機雙資料庫同步整併及雲端同步易用性優化

- **關聯 Issue**：`ISSUE-0053`
- **建立日期**：`2026-10-18`
- **負責角色**：PM Agent
- **審核角色**：SA 系統架構師、設計工程師、軟體工程師、測試工程師

## 1. 背景與問題陳述

在 `ISSUE-0052` 完成了底層資料庫整併比對服務與雙欄裁決介面後，使用者在實際操作中提出三項關鍵痛點與擴充需求：
1. **主畫面功能選單遺漏**：主視窗右上方「`...`」功能選單中包含「備份名片資料 (本機/雲端)...」與「還原名片資料 (本機/雲端)...」，但未提供「同步名片資料庫 (本機/雲端)...」選單項目，導致使用者在首頁選單無法直接開啟同步功能。
2. **雲端同步因憑證缺口無法使用**：使用者開啟同步視窗後，介面僅提示「尚未設定 Google OAuth Client ID，請先透過『圖片同步 ➜ 從 Google Drive 選擇』設定一次憑證」，對話框內未提供 Client ID / Secret 填寫與指引入口，且未登入時點擊同步按鈕直接受阻，使用者無法就地完成設定與使用。
3. **本機雙資料庫同步強烈需求**：使用者強調「同步不只雲端功能，也要能夠讓本地端的兩個資料庫可以同步」。使用者常透過 USB 隨身碟、區域網路共享、外接硬碟、或雲端硬碟本機同步資料夾（如 OneDrive、Dropbox、Google Drive 電腦版）保存名片庫，強烈需要能夠直接選取本機端兩個資料庫檔案（或 ZIP 備份封裝）進行雙向或單向的智慧整併與差異裁決。

---

## 2. 需求目標

升級「名片資料庫同步中心」，提供全功能雙管道（本機檔案 / 雲端）同步體驗：
1. **補齊主功能選單入口**：主視窗「`...`」選單與已存名片總覽皆有顯著之同步入口。
2. **本機雙資料庫同步與整併**：
   - 支援將「目前本機資料庫」與「選定的外部資料庫檔 (`*.sqlite3;*.db`) 或備份封裝 (`*.zip`)」進行比對整併。
   - 支援三種同步方向：
     - **🔄 雙向整併同步**：比對兩端差異並由使用者裁決，整併成果寫回目前資料庫，且同步寫回/更新外部檔案。
     - **⬇️ 從外部檔案整併至本機**：自外部檔案拉取新增或較新資料，整併至目前資料庫。
     - **⬆️ 從本機整併至外部檔案**：將目前資料庫整併更新至外部目標檔案。
3. **雲端同步就地設定與登入優化**：
   - 雲端同步介面內嵌「Google OAuth 憑證設定」展開區塊，使用者可直接輸入 Client ID 與 Client Secret、儲存並一鍵登入，無需切換至其他模組。
   - 提供清楚的錯誤防護與狀態指示。
4. **無縫銜接專業比對與裁決 UI**：
   - 兩管道皆無縫喚起 `DatabaseMergeDialog`，提供四態分類統計、時間差與較新徽章、差異高亮、兩側同時保留 (Keep Both) 及本地備份安全防護。

## 3. 驗收條件 (Acceptance Criteria)

- **AC-01 [主畫面選單]**：主視窗 CommandBar「`...`」選單中，緊鄰「備份名片資料」與「還原名片資料」處新增「同步名片資料庫 (本機/雲端)...」項目，點擊後彈出同步中心對話框。
- **AC-02 [雙模式切換]**：同步中心提供清楚的「📂 本機檔案同步 (推薦)」與「☁️ Google Drive 雲端同步」切換選項，預設為「本機檔案同步」。
- **AC-03 [本機檔案選取]**：本機檔案同步支援使用者瀏覽選取 `*.sqlite3`、`*.db` 或 `*.zip` 檔案，自動校驗檔案有效性並即時顯示目標檔案名稱與路徑。
- **AC-04 [本機同步方向]**：提供三種方向：雙向整併同步、從外部檔案整併至本機、從本機整併至外部檔案。若目標為 ZIP 封裝，雙向同步將自動更新 ZIP 內容或生成整併後的新封裝。
- **AC-05 [雲端憑證就地設定]**：雲端同步頁面提供「⚙️ Google OAuth 憑證設定」Expander，支援直接儲存 Client ID / Secret 與開啟憑證指引；憑證保存後可就地登入。
- **AC-06 [衝突裁決整合]**：比對過程中若發現兩端有名片衝突，自動啟動 `DatabaseMergeDialog`，支援「保留本機」、「採納外部」及「兩側同時保留 (Keep Both)」。
- **AC-07 [安全與備份]**：執行任何寫入前，系統一律自動在 `backups/` 建立快照備份，且整併過程符合 SQLite ACID 交易安全。
