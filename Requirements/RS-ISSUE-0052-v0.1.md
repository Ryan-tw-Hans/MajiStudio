# 需求規格書：多裝置同步之資料庫整併與差異比對裁決功能 (ISSUE-0052)

- **對應 Issue ID**：`ISSUE-0052`
- **需求版本**：`v0.1`
- **建立／更新時間**：`2026-10-18T11:28:00+08:00`
- **負責窗口**：PM Agent

---

## 1. 問題背景與目標

1. **現況痛點**：
   - 目前 MajiStudio 系統支援 Windows 桌面端 (`MajiOCR.Windows`)、iOS PWA 行動版 (`MajiOCR.Web`) 及 Android 端。
   - 使用者在多個裝置上獨立操作（例如：外出使用 iPhone 新增拜訪客戶的名片、在 Windows 辦公室編輯既有名片的備註與公司電話）。
   - 當兩端各自產生資料變更並進行同步（透過 Google Drive 備份包或匯入外部備份 ZIP）時，既有流程容易演變成「整包覆蓋（Overwrite）」，導致較舊端覆蓋較新端，或兩端獨立新增的資料無法合併，造成嚴重的資料遺失風險。
2. **核心目標**：
   - **智慧資料庫整併（Database Merge / Reconciliation）**：在同步或載入外部資料庫時，提供「整併（Merge）」選項，而非僅有單純的整包覆蓋。
   - **結構化差異比對（Diff Comparison）**：
     - 自動比對「目前本機資料庫」與「外部／雲端同步資料庫」中的名片清單（以 `contact_id` UUID 為基準）。
     - 自動分類為：
       1. **新增項（本機獨有）**：外部不存在，本機新增。
       2. **新增項（外部獨有）**：本機不存在，外部/雲端新增。
       3. **內容相同（無變更）**：兩端內容一致。
       4. **資料衝突（雙方皆修改）**：兩端皆有此名片，但欄位、備註、圖片或標籤內容不一致。
   - **明確顯示資料更新時間戳記**：
     - 在比對差異清單與衝突裁決介面中，**必須清楚並列顯示本機更新時間（Local Updated Time）與外部更新時間（Remote Updated Time）**。
     - 醒目標註「較新版本（Newer）」徽章，讓使用者能一眼判斷哪一邊是最新更新。
   - **靈活且安全的衝突裁決（Resolution Strategies）**：
     - 提供批次快捷策略：
       - `以較新更新時間為準 (Keep Newer)`（推薦預設）。
       - `全部保留本機資料 (Keep All Local)`。
       - `全部以外部資料為準 (Keep All Remote)`。
     - 提供單筆/互動檢視：針對特定衝突名片，使用者可展開對照表（欄位級差異比對），勾選決定該筆保留哪一端。
   - **關聯資源整併保證**：
     - 圖片資源（`card_image_assets` 及實體圖片檔）：合併時確保保留被選定版本的圖檔，避免圖檔丟失或破圖。
     - 標籤分類（`contact_tag_catalog`、`contact_record_tags`）：兩端標籤名稱聯集（Union）合併，不重複插入同名標籤。
     - 軟刪除狀態（`pending_delete`）：明確定義刪除 vs. 編輯的衝突裁決邏輯。

## 2. 功能與非功能需求及驗收條件 (AC)

### 2.1 差異比對與分析引擎 (Diff Engine)
* **AC-01（主鍵匹配與狀態分類）**：
  - 系統讀取目標資料庫後，以 `contact_id` (UUID) 進行全量比對。
  - 正確識別出四大集合：
    - `OnlyInLocal`（本機新增）
    - `OnlyInRemote`（遠端/外部新增）
    - `Identical`（雙方內容與關聯值完全一致）
    - `Conflicted`（雙方皆存在但內容欄位、聯絡值、圖片或標籤有差異）
* **AC-02（時間戳記比對與解析）**：
  - 讀取每筆名片的 `updated_at_utc`（若缺失則 fallback 回 `created_at_utc`）。
  - 將 UTC 時間依使用者本機時區轉換為易讀格式（例如：`2026-10-18 11:20:30`）。
  - 自動計算時間差並標註哪一方為 `Newer`（包含具體差異時間，如「較新 2 小時」）。

### 2.2 使用者介面與差異比對裁決檢視 (UI / UX)
* **AC-03（整併預覽與摘要對話框）**：
  - 觸發同步/匯入時，若檢測到兩端皆有資料，彈出「資料庫整併與差異比對」視窗。
  - 頂部顯示摘要統計（如：本機新增 X 筆、雲端新增 Y 筆、完全相同 Z 筆、內容衝突 C 筆）。
* **AC-04（衝突比對清單）**：
  - 針對 `Conflicted` 項目，提供左右並列或卡片式對照檢視：
    - 左側：本機資料（顯示更新時間、姓名、公司、電話、修改處）。
    - 右側：外部/雲端資料（顯示更新時間、姓名、公司、電話、修改處）。
    - 差異欄位以高亮（Highlight）色塊標註。
* **AC-05（裁決控制項）**：
  - 提供全域快捷按鈕：【一鍵以較新時間為準】、【全部保留本機】、【全部採納外部】。
  - 衝突項目支援單筆選擇按鈕（【保留本機】/【保留外部】）。

### 2.3 執行整併與寫入操作 (Merge Execution)
* **AC-06（無衝突項目自動整併）**：
  - `OnlyInRemote`：自動寫入本機資料庫（包含主表、聯絡值、標籤關聯與圖片）。
  - `OnlyInLocal`：本機予以保留，若後續觸發雙向同步則上傳雲端。
  - `Identical`：略過無需重複寫入。
* **AC-07（衝突裁決落實）**：
  - 依使用者裁決之結果，更新或保留對應紀錄。
  - 更新本機資料庫與圖片目錄，並維持事務完整性（Transaction），任一步驟失敗則完整 Rollback。
* **AC-08（完整備份防護）**：
  - 在執行整併寫入前，系統自動在本地 `backups/` 或暫存目錄建立一份整併前的資料庫快照，若整併後使用者反悔或出現異常可隨時還原。

## 3. 系統影響判定與分工規劃

- **系統架構影響 (SA)**：
  - 評估整併模組定位（Windows C# / WinUI 端、iOS Web PWA 端）。
  - 評估大量資料比對效能（In-memory Dictionary 比對 vs. SQLite ATTACH DATABASE 查詢）。
- **資料庫影響 (DBA)**：
  - EAV 結構 (`contact_values`)、標籤關聯 (`contact_record_tags`)、圖片關聯 (`card_image_assets`) 的關聯整併規則。
  - 確保所有合併寫入均符合 SQLite 外鍵與唯一約束。
- **UI/UX 設計 (設計工程師)**：
  - 規劃差異對照介面，確保更新時間與欄位差異一目瞭然，直覺易操作。
- **維運與整合影響**：
  - 確保與現有 Google Drive 同步機制完全相容。

   - 若一端已標記刪除（`pending_delete = 1`），但另一端在刪除後又進行了編輯修改，預設是視為衝突由使用者決定，或是以較新時間為準？
