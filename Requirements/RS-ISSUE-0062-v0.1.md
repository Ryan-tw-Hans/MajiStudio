# 需求規格書：ISSUE-0062 已存名片總覽支援左右區塊（表格與詳細明細）可拖拉調整欄寬（GridSplitter）

- **審核角色**：SA 系統架構師、設計工程師、軟體工程師、測試工程師

## 1. 背景與問題陳述

在 MajiStudio Windows 桌面端 (`MajiOCR.Windows`) 之「已存名片總覽」介面（`SavedCardsTablePanel`）中，版面佈局分為：
- **左側區塊**：名片清單表格（`_tableContainerGrid`），呈現 CheckBox 多選、姓名、公司、職稱、電話、Email、標籤、建立時間與圖片狀態。
- **右側區塊**：選取名片的詳細資訊抽屜（`_detailDrawerBorder`），呈現名片縮圖、大圖檢視、標籤與各欄位明細。

目前左右兩區塊為固定比例/固定寬度配置（左側 Star 自適應，右側抽屜固定為 340px，中間只有固定 ColumnSpacing 12px），使用者無法依照目前螢幕解析度或名片欄位內容的長短，自由調整左右兩側的可視寬度。
使用者提出需求：「希望左右兩個區塊中間的間隔可以透過拖拉來調整左右兩區塊的寬度」。

---

## 2. 需求目標與功能範圍

1. **左右分割拖拉條（Splitter Divider）**：
   - 於左側表格與右側詳細抽屜之間加入可拖曳的分割拖拉條（利用 WPF 原生 `GridSplitter` 或同等流暢互動控制項）。
   - 滑鼠懸停於分割條上方時，游標自動切換為水平雙向箭頭（`Cursors.SizeWE`）。
   - 分割條具備優雅之視覺回饋：常態下呈現半透明分隔線，懸停（MouseOver）或拖曳（IsDragging）時高亮顯示（呈現強調色 Accent / BorderBrush），並於正中央繪製精緻的拖拉手把（Grip Handle），提供明確的視覺可觸發指引。

2. **流暢拖拉與安全邊界防呆（Min / Max Width Constraints）**：
   - 支援即時（Realtime / Live）拖曳調整寬度，左側名片表格與右側詳細抽屜流暢同步重排。
   - **右側抽屜最小寬度**：設定安全最小寬度（`MinWidth = 260px`），避免拖曳過窄造成欄位內容被截斷或擠壓。
   - **右側抽屜最大寬度**：設定安全最大寬度（或左側表格保留 `MinWidth = 360px`），避免右側拉過大將左側表格完全遮蔽。

3. **抽屜收合/展開連動與寬度記憶（Drawer Toggle Compatibility & Width Memory）**：
   - 當使用者點擊「📋 收合明細」時，右側抽屜與拖拉條一併收合（寬度為 0 / Collapsed），左側表格佔滿全部空間。
   - 當使用者再次點擊「📋 展開明細」時，右側抽屜自動還原至使用者先前拖拉調整之自訂寬度（若使用者尚未調整過，則還原預設值 340px），拖拉條同步恢復可見與可拖拉。

---

## 3. 驗收條件 (Acceptance Criteria)

- **AC-01 [拖拉條可見性與游標]**：在已存名片總覽明細展開狀態下，左側表格與右側明細抽屜之間可見垂直分隔條；滑鼠移入時游標變為左右雙向箭頭 (`SizeWE`)，且分割條具備視覺懸停反饋。
- **AC-02 [滑鼠拖曳調整寬度]**：按住分割條向左拖曳時，右側抽屜變寬、左側表格相應縮小；向右拖曳時，右側抽屜變窄、左側表格相應變寬，畫面內容流暢即時刷新。
- **AC-03 [邊界限制保護]**：向左或向右極限拖曳時，右側抽屜不會小於最小限制寬度（260px），且左側名片表格不會被壓縮至完全看不見（保留至少 360px）。
- **AC-04 [收合與展開記憶]**：拖拉調整自訂寬度後（例如調整至 450px），點選「📋 收合明細」，抽屜完全隱藏；再次點選「📋 展開明細」，抽屜正確恢復為 450px 寬度，而非重置為初始 340px。
- **AC-05 [雙擊重置預設寬度]**：雙擊分割拖拉條時，右側抽屜寬度自動重置回預設寬度（340px），提供使用者快速復原機制。
