## 1. 問題背景與目標

1. **現況痛點**：
   - 既有系統偏向「備份（Backup）」與「還原（Restore）」之靜態檔案概念，操作藏於還原選單內，未能直觀體現日常跨裝置「同步」的使用情境。
   - 使用者明確要求：
     - 將整併功能正式定位於專門的「**同步功能（Sync Hub）**」內。
     - 不需把其視為冷門的還原動作，而是隨時可以指定資料庫進行同步。
     - 支援明確的**同步方向選擇**：
       1. **雲端 ➔ 本機 (Cloud to Local)**：自雲端同步最新資料回本機，並執行差異比對與整併（顯示更新時間、支援兩側同時保留）。
       2. **本機 ➔ 雲端 (Local to Cloud)**：將本機最新名片庫直接同步更新至雲端。
       3. **雙向同步 (Bidirectional Sync)**：先自雲端拉取比對並整併至本機，整併確認後自動將最新結果回推至雲端，實現多端完全一致。
2. **核心目標**：
   - 於頂部工具列或匯出/同步選單中提供專屬入口：【🔄 資料庫雲端同步】。
   - 打造專屬的「資料庫同步中心」對話框，清楚呈現：
     - 目前雲端資料庫狀態與最後更新時間。
     - 本機資料庫狀態與最後更新時間。
     - 三大同步方向模式選取：【🔄 雙向同步 (推薦)】、【⬇️ 從雲端同步至本機】、【⬆️ 從本機同步至雲端】。
   - 整合差異比對裁決引擎：
     - 若涉及雲端至本機的同步，自動觸發差異比對視窗，明確顯示雙方更新時間與差異欄位，支援【保留本機】/【採納外部】/【👥 兩側同時保留】。
     - 若為雙向同步，整併完成後自動接續將最新資料庫封裝上傳雲端，一氣呵成。

## 2. 功能與非功能需求及驗收條件 (AC)

### 2.1 同步中心對話框 (`DatabaseSyncDialog`)
* **AC-09（同步模式選取）**：
  - 提供三種同步方向模式：
    - `Bidirectional`：雙向同步（下載比對整併 ➔ 上傳同步雲端）。
    - `PullOnly`：僅從雲端同步至本機（下載比對整併）。
    - `PushOnly`：僅從本機同步至雲端（直接打包上傳）。
* **AC-10（雲端與本機版本狀態摘要）**：
  - 登入 Google 後，自動顯示雲端目前最新資料庫的時間、名片數與平台來源。
  - 同時並列顯示本機名片數與最後修改時間。

### 2.2 雙向同步工作管線 (Bidirectional Sync Pipeline)
* **AC-11（自動化串接整併與回推）**：
  - 模式選取「雙向同步」並執行時：
    1. 步驟一：下載雲端資料庫暫存檔。
    2. 步驟二：比對本機與雲端差異，若有衝突彈出裁決對話框；若無衝突自動整併。
    3. 步驟三：本機整併完成後，自動將最新的本機資料庫重新打包並呼叫 Google Drive API 上傳覆蓋/更新雲端最新版本。
    4. 步驟四：顯示「🎉 雙向同步完成！本機與雲端已同步至最新一致狀態」。
