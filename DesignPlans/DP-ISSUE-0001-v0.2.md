## 1. 設計目標

- 讓使用者明確知道 App 正在對焦、即時辨識、等待鎖定、重新掃描、保存影像或保存聯絡人資料。
- 使用者只需點選一次候選文字，即可阻止背景 OCR 造成欄位跳動。
- 欄位判錯時，使用者能在不重掃的情況下重新分類文字。
- 「完成」的意義必須可理解：同一筆完成記錄含有可查看的原始名片影像與結構化聯絡人資料。
- 所有會使資料離開手機、寫入 Android Contacts 或刪除保存影像的動作，維持可見、可理解且可取消。

## 2. 畫面與資訊層級

### 2.1 掃描畫面

1. 頂端：目前辨識模式。初始顯示「離線 OCR」；雲端與 AI 為明確的次要按鈕。
2. 中央：相機預覽與名片取景框。框外顯示「對焦中」、「即時辨識中」或「請重拍」狀態。
3. 預覽上：以細框標示目前 Live 候選所在區域；Locked 候選使用明顯但不刺眼的鎖定樣式。
4. 下半部：聯絡人草稿卡片，依欄位顯示候選文字與其狀態。
5. 底部：重拍／停止掃描、手動新增、完成存檔。雲端 OCR 與 AI 不得與完成按鈕混淆。

### 2.2 聯絡人草稿卡片

每筆候選至少顯示：

- 文字值。
- 目前欄位名稱。
- 資料來源：離線 OCR、雲端 OCR、AI 或手動。
- Live、Locked 或重新掃描中的可讀狀態。
- Locked 時可展開的欄位名稱下拉選單。

完成區塊必須另列：

- 「原始名片影像：將與此聯絡人一起保存在本機」的清楚提示。
- 可見的影像縮圖或非敏感的影像佔位預覽；縮圖只是畫面呈現，不另行代表長期保存的衍生影像資產。
- 「保存到此手機，不會自動同步、上傳或新增到系統聯絡人」的說明，直到 D-06、雲端與 Contacts 動作各自被確認。

### 2.3 保存進度與完成結果

按下完成後，掃描畫面不應立即消失，而是進入 `Saving` 狀態，按順序顯示：

1. 「正在保存原始名片影像」；
2. 「正在保存聯絡人資料」；
3. 「正在確認資料完整」；
4. 只有兩種資料都 Ready 時，顯示「已保存原始名片影像與聯絡人資料」。

使用者在保存期間可等待、取消尚未開始的外部匯出，或在可安全取消的時間點取消整筆保存；UI 不得在資料仍為 Pending 時顯示完成。

### 2.4 後續本機查詢詳情

本版只定義資料詳情的最低互動：

- 列表顯示姓名、公司、完成時間與「含原始名片影像」狀態。
- 點選一筆資料後顯示結構化欄位及其原始名片影像。
- 影像缺失或驗證失敗時，保留聯絡人欄位並顯示「原始影像目前無法讀取」；不可用錯誤影像或空白畫面掩蓋狀態。
- 圖片分享、另存相簿、跨 App 開啟、同步及匯出均不屬於本版互動範圍。

## 3. 核心互動規則

| 使用者動作 | 預期結果 | 不得發生的行為 |
| --- | --- | --- |
| 對焦可用 | 開始更新 Live 候選。 | 覆寫既有 Locked 值。 |
| 點選 Live 候選 | 將該候選的文字與欄位名稱鎖定。 | 因下個 OCR 影格而變更值。 |
| 點選 Locked 候選 | 顯示「重新掃描此項」狀態並只解除該候選。 | 清空其他 Locked 值或背景自動存檔。 |
| 在 Locked 候選選擇新欄位名稱 | 將既有文字移到選定欄位，不重跑 OCR。 | 靜默取代另一個 Locked 值。 |
| 目標欄位已有 Locked 值 | 顯示保留既有、加入另一筆、取代三個明確選項。 | 自行選擇覆寫策略。 |
| 手動編輯文字 | 保留文字為手動值並鎖定。 | 被新的 OCR 結果回寫。 |
| 點選完成 | 顯示影像與聯絡人雙重保存進度，兩者 Ready 才顯示成功。 | 只有 SQLite 或只有影像完成就顯示成功。 |
| 點選雲端 OCR 或 AI | 顯示服務、將傳送的資料、取消與同意。 | 因本機已保存影像而免除同意。 |
| 點選 Android Contacts 匯出 | 開啟系統確認流程，並分開顯示匯出結果。 | 將 SQLite 保存成功誤顯示為系統聯絡人已新增。 |

## 4. 候選與保存狀態的視覺規則

| 狀態 | 必須顯示 | 可操作性 |
| --- | --- | --- |
| Focusing | 對焦／品質提示。 | 重拍、手動掃描、選取影像。 |
| Live | 「辨識中」及可更新候選。 | 點選鎖定、手動編輯。 |
| Locked | 鎖定文字、來源、欄位名稱及重新掃描入口。 | 改欄位名稱、手動編輯、再次點選重新掃描。 |
| RescanRequested | 僅該候選的等待新結果提示。 | 取消、保留舊值、手動輸入。 |
| Saving | 影像、聯絡人資料及完整性確認的進度文字。 | 不接受會造成草稿歧義的新 OCR 更新。 |
| Completed | 原始影像與資料已保存的摘要。 | 查看本機資料、可選 Android Contacts 匯出。 |
| ImageMissing / Failed | 保留聯絡人欄位並說明影像或保存失敗。 | 重試、保留草稿、取消或在日後依資料生命週期處理。 |

色彩只能輔助狀態，必須配合文字、圖示與螢幕閱讀器描述。Locked、Saving、Completed、Failed 不能只用不同顏色區分。

## 5. 錯誤與回復體驗

- 相機權限拒絕：提供相簿選取、手動輸入與如何重新授權的說明。
- 對焦或畫面品質不足：顯示「請將名片置於框內並保持清晰」，不製造假候選。
- OCR 沒有文字：保留手動建立聯絡人與重拍。
- 影像寫入失敗：顯示「原始名片影像尚未保存」，保留草稿並提供重試；不能自動降級為只保存文字。
- SQLite 寫入或定稿失敗：顯示未完成存檔與真實失敗階段，保留草稿並提供重試；不可顯示成功。
- App 重啟復原：若 Pending 資產已恢復為 Ready，顯示一次性的可理解結果；若無法復原，說明何種資料已保存、何種資料未完成。
- Android Contacts 匯出取消：顯示本機影像與聯絡人已存檔、系統聯絡人未建立的真實狀態。

## 6. 無障礙與可用性

- 每個候選與狀態須有文字描述，不能只用顏色判別。
- 點選區域須適合手指操作；鎖定、重新掃描與下拉選單不可依賴過小圖示。
- 對焦、OCR、影像保存、SQLite 保存、外傳與錯誤狀態須可由螢幕閱讀器讀出。
- 欄位名稱與候選文字應允許字體放大、換行與長字串顯示。
- 初次使用須以簡短說明告知「點選文字即鎖定，再點一次即可重新掃描」及「完成會保存原始名片影像與聯絡人資料到此手機」。

## 7. 設計驗收條件

1. 對焦可用後，未鎖定候選可以更新，但任何 Locked 值連續掃描後仍不變。
2. 重掃單一候選不改變其他 Locked 欄位。
3. 重新分類在不重跑 OCR 的情況下完成，並在衝突時要求使用者選擇處理方式。
4. 完成按鈕後，使用者能看見原始影像與聯絡人資料的保存進度，且只在兩者皆完成時看到成功結果。
5. 保存故障或影像缺失的畫面清楚區分，不誤導使用者認為資料完整。
6. 離線、雲端 OCR、AI 文字、AI 影像的資料傳送提示可以清楚分辨。
7. Android Contacts 匯出結果必須與本機影像／SQLite 存檔結果分開呈現。

## 8. 尚待確認的設計決策

- D-06：資料庫加密與 Auto Backup／裝置轉移規則確認後，首次完成畫面是否需要額外告知「不會／會備份到帳戶」。
- D-07：刪除聯絡人時是否同步刪除原始影像，以及是否需要回收桶或不可逆刪除確認。
- 是否在掃描畫面同時顯示所有 OCR 文字覆蓋框，或只顯示與聯絡人欄位相關的候選。
- 重掃時是否需要讓使用者選取名片局部區域，或只重啟整張名片的即時 OCR。
- 本機查詢頁面的完整列表、搜尋列與篩選器設計，將在使用者提出查詢 UI 範圍後另立需求。
