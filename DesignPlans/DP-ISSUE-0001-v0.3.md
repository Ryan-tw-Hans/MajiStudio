## 1. 使用者溝通原則

Android Backup、雲端 OCR／AI 與 Android Contacts 是三種不同的外部行為，畫面不可混用名稱、圖示、同意文字或成功訊息。

| 行為 | 正確說明 | 不得說明為 |
| --- | --- | --- |
| Android Auto Backup／裝置轉移 | Android 系統可依裝置或帳戶設定備份／轉移已保存的原始名片影像與聯絡人資料。 | 已立即上傳、一定可還原、已傳給 AI。 |
| 雲端 OCR／AI | 使用者逐次同意後，指定資料才透過受控服務處理。 | Android Backup 的一部分。 |
| Android Contacts 匯出 | 使用者確認後將欄位交給 Android 系統聯絡人流程。 | 本機保存或 Backup 已成功。 |

## 2. 新增畫面與狀態

### 2.1 初次使用／資料設定提示

首次建立名片前，或在資料設定頁，必須以可略過但可再次查看的說明呈現：

> 「原始名片影像與已完成的聯絡人資料會保存於此 App；依 Android 裝置與帳戶設定，它們也可以用於系統備份與換機轉移。」

畫面需附帶：

- 「這不是雲端 OCR／AI 傳送」的說明連結或輔助文字。
- 可前往系統備份設定的指引，但不在 App 內假裝控制帳戶、排程或備份成功結果。
- 與 App 額外加密、保存期限與刪除策略相關的設定入口，在決策完成前顯示為「規則待確認」，不能假造選項。

### 2.2 完成保存畫面

既有 `Saving` 與 `Completed` 狀態增加：

- 成功後顯示「已保存到此 App；此資料已允許納入 Android Backup／換機轉移」。
- 不使用「已雲端備份」或「已同步」字樣，除非未來能從 Android 平台取得可驗證狀態。
- 顯示原始名片影像縮圖／預覽和結構化欄位摘要；兩者都 Ready 才可進入成功畫面。
- 若本機保存成功但尚未有可驗證的系統備份，仍只說「本機已保存」。

### 2.3 還原後的本機查詢

| 狀態 | 列表／詳情顯示 | 可操作性 |
| --- | --- | --- |
| Ready | 「影像與聯絡人資料可用」。 | 可查看原始名片影像與欄位。 |
| ImageMissing | 「聯絡人資料已還原，原始名片影像無法讀取」。 | 可保留欄位、重新掃描或依未來資料管理規則處理。 |
| Pending / Failed | 「保存或還原尚未完成」。 | 不列為一般完成資料；可由 Recovery 結果導向重試或安全清理。 |
| ContactsExportState | 另列系統聯絡人匯出結果。 | 不改變本機／Backup 的真實狀態。 |

## 3. 互動規則補充

| 使用者動作／事件 | 預期結果 | 不得發生的行為 |
| --- | --- | --- |
| 第一次建立名片 | 顯示 Android Backup／換機轉移的資料範圍說明。 | 將此說明包裝成雲端 OCR 或 AI 同意。 |
| 完成保存 | 只確認本機影像與聯絡人資料都 Ready；以非保證語句說明其可納入系統備份。 | 顯示「已上傳」、「已同步」或「已復原」。 |
| 使用者點選雲端 OCR／AI | 顯示逐次資料外送同意。 | 因 Backup 已允許就略過同意。 |
| App 在還原後啟動 | 先執行 Recovery，再顯示可用資料與缺失資料。 | 直接把所有資料庫 row 當作完整名片。 |
| 備份容量可能不足 | 顯示資料管理或影像大小政策的說明。 | 靜默壓縮、刪除原始影像或取消保存。 |
| Android Contacts 匯出取消 | 顯示本機資料仍可用；Backup 可用性不因此改變。 | 把取消誤顯示為本機保存失敗。 |

## 4. 無障礙與驗收補充

- Android Backup、雲端 OCR／AI、Android Contacts 各自有可由螢幕閱讀器辨識的完整名稱與狀態。
- Backup 說明必須使用清楚語句，而非只用雲朵圖示、顏色或帳戶圖標。
- 資料還原不完整時，畫面需讀出哪一種資料可用、哪一種資料缺失、下一步可做什麼。
- 驗收時，使用者應能在不閱讀技術文件的情況下正確區分「已保存到本機」、「允許系統備份」與「已傳送給 AI」三種結果。

## 5. 待決設計項目

- D-06-B：App 層額外加密確定後，是否需要顯示加密狀態、金鑰變更或無法解密的還原提示。
- D-07：刪除聯絡人時是否同步刪除原始影像，以及是否提供回收桶或不可逆刪除確認。
- D-08：原始影像大小／品質策略確定後，是否在拍攝前顯示容量預估或在資料設定頁提供管理入口。
- 本機查詢頁面的完整列表、搜尋列與篩選器，將在使用者提出查詢 UI 範圍後另立需求。
