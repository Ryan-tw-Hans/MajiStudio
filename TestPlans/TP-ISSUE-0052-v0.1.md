# 測試計畫書：多裝置同步之資料庫整併與衝突差異比對 (TP-ISSUE-0052-v0.1)

- **對應 Issue ID**：`ISSUE-0052`
- **測試版本**：`v0.1`
- **制定日期**：`2026-10-18`
- **測試角色**：測試工程師 Agent

---

## 1. 測試目標與範疇

驗證 `ISSUE-0052` 所實作之「多裝置同步之資料庫整併與衝突差異比對」引擎、裁決邏輯與資料保全能力，確保：
1. **比對引擎精準性**：精確識別 `OnlyInLocal`、`OnlyInRemote`、`Identical`、`Conflicted` 四大類別。
2. **時間戳記判讀**：正確計算並呈現本機與外部更新時間差與 `🟢 較新 (Newer)` 判定。
3. **裁決策略落實**：
   - `KeepNewer`（以較新為準）
   - `KeepLocal`（保留本機）
   - `KeepRemote`（採納外部）
   - `KeepBoth`（兩側同時保留：派生新 UUID、加註同步複本、獨立複製圖檔與標籤）
4. **安全交易與備份快照**：整併前建立快照，整併過程於單一 Transaction 內執行。

---

## 2. 測試案例規劃 (Test Cases)

| 測試編號 | 測試項目 | 驗證重點與預期結果 |
| :--- | :--- | :--- |
| **TC-01** | 比對引擎分類精準度 | 驗證本機獨有、外部新增、完全一致與內容衝突等 4 種狀態被 100% 精確識別。 |
| **TC-02** | 時間戳記與較新判定 | 外部更新時間晚於本機時，`IsRemoteNewer` 為 `true`，時間摘要正確呈現領先時間。 |
| **TC-03** | KeepNewer 裁決整併 | 外部較新時更新本機，本機較新時保留本機。 |
| **TC-04** | KeepLocal 裁決整併 | 本機衝突項目內容完全不變，外部修改被忽略。 |
| **TC-05** | KeepRemote 裁決整併 | 本機衝突項目被外部版本完全覆寫（主表、EAV、標籤）。 |
| **TC-06** | KeepBoth 兩側同時保留 | 本機原名片保留原 UUID 與內容；外部名片派生全新 UUID 並標記 `(同步複本)`，名片總數增加，兩側修改皆完整保留。 |
| **TC-07** | 安全快照防護驗證 | 驗證整併執行前 `backups/` 自動產生 `pre_merge_*.sqlite3` 完整備份。 |
